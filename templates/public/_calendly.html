{% comment %} Calendly popup assets plus the bridge that gets an invitee OUT of the iframe. This is no longer the front door — our own panel (public/_schedule_form.html) books through Calendly's API instead. It stays because it is the FALLBACK: if availability or booking fails, the panel calls window.openCalendlyPopup() and the visitor can still book. Deleting it would turn an API outage into a total loss of the booking path (plan decision 2). The event type's "Redirect to an external site" setting navigates the POPUP's iframe, not the page behind it — on its own the visitor ends up on our thanks page inside a modal, still on whatever page they started from. Calendly posts `calendly.event_scheduled` to the parent window, so the parent does the navigation. Consequence, by design: the parent cannot read the iframe's cross-origin URL, so the popup path lands on the generic thanks page while direct-link traffic gets the personalized one. schedule_thanks handles both. The origin check is not optional — this listener runs on every public page, and window.postMessage can be called by any frame on the page. {% endcomment %}
